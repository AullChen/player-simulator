# 球员模拟器

一个基于 Flutter 的足球职业生涯模拟器。用户可以把比例转盘、动态选择或自定义数据转换成完整球员档案，并调用自有故事 API 生成中英文生涯故事。

## 已实现模式

### 全随机 · 真实概率

- 按“个人 → 俱乐部 → 国家队”的时间顺序生成 40–80+ 个动态转盘步骤。
- 转盘扇区角度严格等于 `该项权重 ÷ 总权重 × 360°`。协会转盘使用 FIFA 2023 报告的 128,694 名职业球员总数；英格兰 5,582 人，对应 4.34% 扇区。
- FIFA 报告逐项公布的 27 个协会人数直接进入权重表，其余 62,992 人保留为可继续展开的尾部桶。
- 协会人数代表注册地而非国籍；国籍使用 FIFA 世俱杯完整 81 国名单，先抽洲足联，再在洲内抽到具体国家，不出现“其他国家”。
- 每次转盘停止后锁定结果约 2 秒，再进入下一项。
- 青训入营、职业首秀、每次转会、加盟当前俱乐部、末次合同开始、合同结束和退役共享同一年龄轴。
- 已抽取结果旁提供编辑入口，可载入完整档案手动校正；保存前会拒绝互相矛盾的时间线。
- 生成出生与公民身份、身体和号码、注册合同、经纪人、俱乐部与国家队履历。
- 生成结构化转会/伤病/模拟身价轨迹，以及分赛事出场、首发、分钟、进球、助攻和纪律数据。
- 为提高游戏节奏，巅峰能力先按产品目标分段：80+ 占 50%、70–79 占 40%、70 以下占 10%；分段内继续使用原成长曲线的条件概率。
- 支持固定随机种子测试，保证概率引擎可复现。

### 模拟球员 · 生涯选择

- 用户只指定国籍和位置。
- 可选随机长度、5 个关键节点、每 3 年 8 个节点、每 2 年 11 个节点或 15–36 岁逐年 22 个节点。
- 随机长度不再预生成节点数；每个选项都独立计算退役概率，选择后才决定是否还有下一次。生涯可能首轮因场外严重车祸结束，也可能极罕见地踢到 60 岁。
- 每个年龄节点都从独立策划文件中的 100 个候选分支筛选和加权，再向玩家展示 3–5 个。
- 完整人物模型包含左右腿、左右臂、速度、力量、体力、健康、恢复、技术、智力、决策、纪律、韧性、团队、士气、声望和运气。
- 每次选择会改变人物数值、训练负荷和伤病风险；这些状态又决定后续选项的可见性与出现权重。
- 人物数值与选项增减只在内部参与计算，不向玩家显示；每个选项以明确概括标题和“当时 / 你的决定”两段文字组成完整微型故事，不再额外显示“是否留队”的独立提醒。
- 完成后生成从首秀到退役的逐年内部快照，供故事 API 描写状态、角色、恢复和声望变化；提示词禁止把隐藏评分直接写给读者。
- 转会、外租和生涯俱乐部从 FIFA 2025 世俱杯 32 支真实参赛俱乐部目录中动态选择。

### 梦想球员 · 自由创作

- 可填写身份与身体、位置号码、青训能力、俱乐部合同、经纪人和国家队信息。
- 可逐行录入转会、伤病、身价和分赛事统计；多行框可随回车持续增长，支持竖线、逗号、分号或 Tab，非关键尾部字段可省略。
- 俱乐部列表会自动转换为生涯时间轴。

### 设置与本地档案

- 设置页可随时切换简体中文或英文。
- 可选择 OpenAI、Anthropic 或 DeepSeek 协议，配置 API 密钥、模型和可选自定义地址。
- “测试连接”会发送一次极短请求，并明确反馈鉴权、权限、模型、限流和服务端错误。
- 球员档案保存在本地，支持查看、去重保存和删除；当前最多保存 50 份。
- 访问令牌与档案通过 `shared_preferences` 保存在设备普通应用存储中，不等同于安全密钥库。

## 运行

环境要求：Flutter 3.32 或兼容 Dart 3.8 的 Flutter 版本。

```powershell
flutter pub get
flutter run
```

项目使用 Flutter 官方本地化组件和 `shared_preferences`。首次解析依赖需要访问 Pub；缓存完整后可离线构建。

## 接入故事 API

未配置 API 时，结果页使用本地示例生成器，方便完整演示。用户可以直接在应用设置页填写接口，也可通过构建参数提供默认值：

```powershell
flutter run `
  --dart-define=STORY_API_PROVIDER=deepSeek `
  --dart-define=STORY_API_TOKEN=your-token `
  --dart-define=STORY_API_MODEL=deepseek-v4-pro
```

`STORY_API_PROVIDER` 可使用 `openAi`、`anthropic` 或 `deepSeek`。未传
`STORY_API_URL` 时使用供应商官方地址；设置页仍允许填写 OpenAI/Anthropic
兼容网关。没有 API 密钥时继续使用本地示例，不会发送远程请求。

| 协议 | 默认地址 | 鉴权 | 默认模型 |
| --- | --- | --- | --- |
| OpenAI | `https://api.openai.com/v1/chat/completions` | `Authorization: Bearer` | 不猜测，用户填写账户可用模型 |
| Anthropic | `https://api.anthropic.com/v1/messages` | `x-api-key` + `anthropic-version: 2023-06-01` | `claude-opus-4-8` |
| DeepSeek | `https://api.deepseek.com/chat/completions` | `Authorization: Bearer` | `deepseek-v4-pro` |

OpenAI 使用 Chat Completions 的 `model`、`messages` 和 `stream: false`，
并从 `choices[0].message.content` 读取故事。Anthropic 使用 Messages API，
设置 `max_tokens`、顶层 `system` 和 `messages`，再合并响应中的文本内容块。
DeepSeek 使用 OpenAI Chat Completions 结构，并在正式生成时额外发送：

```json
{
  "thinking": {"type": "enabled"},
  "reasoning_effort": "high",
  "stream": false
}
```

连接测试会要求供应商只回复 `OK`。为缩短时间和减少费用，DeepSeek 连接测试使用
`thinking: {"type": "disabled"}`；故事生成才启用高强度思考。测试结果会显示耗时，
并区分 HTTP 400、401、403、404、429 和 5xx。标准供应商响应之外，客户端仍保留
对旧版顶层 `story`、`text`、`content` 和 `data.story` 的读取兼容。

`football-biography-v3` 会把完整球员档案 JSON 和模拟人生逐年快照嵌入用户消息，并要求模型将其作为唯一事实来源，
严格保持年龄和赛季顺序，
禁止虚构具名俱乐部、冠军、伤病或引语，并把逐年评分变化转译为竞技状态而不是暴露能力值、人物模型和游戏机制。
中文目标为约 1800–2600 字的足球杂志特写，而不是逐字段报表。

> `--dart-define` 的值会进入客户端构建产物，不应被当作安全的密钥存储。生产环境应让 `STORY_API_URL` 指向自己的后端代理，由后端持有模型供应商密钥、执行鉴权和限流。Web 端还需要接口允许对应来源的 CORS 请求。

### 公开仓库安全

- 仓库不包含可用的模型供应商密钥；测试中的 `test-token`、`anthropic-key` 等均为无效占位符。
- 不要提交 `.env`、移动端服务配置、签名证书或导出的本地球员档案；这些常见文件已加入 `.gitignore`。
- 设置页输入的 API Key 和保存的球员档案位于设备普通应用存储中。共享设备应使用可撤销、低权限的密钥，生产部署应优先使用后端代理。

## 真实概率说明

当前版本使用“公开原值 + 派生概率 + 显式产品建模”。FIFA Professional Football Report 2023 用于协会注册人数；FIFA Club World Cup 2025 完整名单用于 81 个具体国籍及洲足联聚合权重，并提供真实俱乐部目录；FIFA 2025 年 1 月国际转会快照用于校准 24.9 岁平均转会年龄和 17.7% 有偿转会比例。退役原因参考 Koch 等人的德国职业球员研究，合同脆弱性参考 FIFPRO 全球就业报告，伤愈后的风险修正参考职业足球复出研究。Transfermarkt 公开资料页仅用于确定常见球员字段类型，不抓取其数据库，也不复刻其专有估值。

由于公开来源的样本范围不同，项目明确区分精确公开值、派生权重与产品建模值。正式上线前仍应接入有授权、带版本且覆盖口径一致的数据集，并记录：

- 数据来源、采样时间和覆盖联赛；
- 在册球员、出场球员还是分钟数加权的统计口径；
- 缺失值、双国籍、租借、自由转会和退役球员的处理方法；
- 每次概率表更新的版本与回归结果。

详细方法见[概率模型说明](docs/probability-model.md)、[人生事件策划说明](docs/life-event-design.md)和[公开数据来源](docs/public-data-sources.md)。

## 项目结构

```text
lib/
├── data/       # 足球目录、概率表和独立人生事件库
├── domain/     # 球员档案、人物属性、职业章节和统计模型
├── screens/    # 三种模式、首页和结果档案
├── services/   # 随机引擎、生涯选择引擎、故事 API
├── theme/      # 颜色、排版和组件主题
└── widgets/    # 转盘与通用展示组件
```
