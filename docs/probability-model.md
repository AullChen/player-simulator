# 概率模型说明

## 目标

随机模式需要同时满足两个条件：

1. 单项结果符合可解释的职业足球分布；
2. 组合结果彼此一致，例如门将通常更高，中锋进球率通常高于中后卫，巅峰能力影响国家队出场和转会费。

因此本项目不是把所有字段独立摇号，而是先抽基础身份，再用条件规则生成职业结果。

## 当前生成顺序

```text
国籍 / 位置 / 惯用脚
        ↓
青训等级 → 初始能力 → 成长曲线 → 巅峰能力
        ↓
身高 / 第二位置 / 比赛风格
        ↓
首秀与退役年龄 → 转会次数 → 俱乐部轨迹
        ↓
出场 / 进球 / 助攻 / 国家队 / 转会费
        ↓
冠军 / 个人荣誉 / 伤病记录
```

基础加权表位于 `lib/data/football_catalog.dart`，条件生成逻辑位于 `lib/services/random_career_generator.dart`。

## 建模原则

- 惯用脚以右脚为主，左脚次之，双足最少。
- 位置权重按一套常见职业队阵容的人员构成近似，而不是按首发 11 人简单等分。
- 青训等级影响初始能力，但不直接锁死上限；低级别青训仍保留小概率成长为顶级球员。
- 成长曲线使用长尾分布，世界级巅峰是罕见事件。
- 转会次数使用偏向 1–4 次的离散分布，并允许一人一城或高流动生涯。
- 身高按位置设置不同区间。
- 进球率和助攻率按位置变化，再叠加随机扰动。
- 国家队出场、冠军和个人荣誉随巅峰能力增加，但不保证必然获得。

## “真实”需要明确统计口径

同一问题会因口径产生完全不同的概率。例如“球员来自哪个国家”至少可以按以下方式统计：

- 全球注册职业球员人数；
- 五大联赛在册人数；
- 顶级联赛实际出场人数；
- 比赛分钟数；
- 转会市场记录数量。

产品上线前必须选定一种口径，不能混合来源后仍称为真实概率。

## 生产数据升级建议

建议把静态表替换为带版本的 JSON 数据包，并在构建时执行以下检查：

- 所有权重为正数且分组总和符合预期；
- 国家、联赛、俱乐部和赛季之间的外键完整；
- 同一球员的租借和永久转会不会重复计数；
- 固定种子的历史快照可重放；
- 至少运行一万次蒙特卡洛抽样，对输出分布做区间回归；
- UI 显示当前数据版本和统计口径。

当前测试使用 100 个固定种子检查合理边界，适合 MVP 回归，不等同于统计学上的生产校准。
